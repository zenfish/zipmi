Execution model and limits

Named selector operations prepend their proven Fujitsu IANA and selector bytes. Twenty-two read-only selectors are constrained to a four-byte request and can run without --unsafe. Other runnable names require --unsafe pending individual safe promotion; this includes some decoded standard reads as well as state-changing or partial commands. The two group-52 Redfish bootstrap names are Admin/channel-0f host-interface routes and are not runnable over zipmi's LAN transport. For command 2c/02, the named A5 form is not an allowlist: any second byte reaches the credential path. Parent 2e and 2c dispatch names cannot be sent without selecting a leaf. Three distinct LUN-3 FRU handlers are documented in the firmware reference but not exposed as LAN names after the target returned C0 on LUN 3.

High-impact findings

  • 2e/01 is admitted at User privilege and multiplexes power reads with state-changing selectors 17, 1b, 1c, and 20.
  • 2e/e0 04 is a NVRAM/IDPROM maintenance multiplexer, not a safe read; it can restore FRU data or write IDPROM.
  • 2e/F1 11/40 can change GUID/configuration state before an error reply; 40 returns C7 after its write attempt.
  • 2c/02 group 52 can create and return user credentials on the host channel with any second byte; it is never a safe DCMI power read.
  • 34/38–39 persists configuration and has a statically proved undersized-page copy path.
  • 2e/F5 selectors 52, a5, and f8 reach I2C write/read, persistent POH reset, and user deletion respectively; flash and raw PECI routes also remain high-impact. These are static findings, not live probes.

See the zBMC binary-evidence reference for handler addresses, platform gates, and the distinction between decoded and partial leaf contracts.
