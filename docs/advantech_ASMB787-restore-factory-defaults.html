ASMB-787 restore-defaults execution chain

The ASMB-787 firmware registers NetFn 0x32 / Cmd 0x66 as AMIRestoreDefaults. Correct decoding of CmdHndlr_T gives privilege Administrator (0x04) at offset +1 and request length 0 bytes at offset +8.

Earlier documentation swapped those fields and incorrectly called the command privilege 0, remotely unauthenticated, and a backdoor. Those claims are withdrawn. A LAN caller must establish an Administrator IPMI session. The static entry alone does not prove unauthenticated KCS reachability.

Execution behavior

Static analysis shows the handler queues pending task 0x3f and returns completion code 0 before the task finishes. The firmware carries restoredefaults.sh, whose destructive branch replaces /conf from /etc/defconfig, but the exact pending-task-to-script call site was not recovered. On the emulated image, the raw command was accepted and a reprovision storm followed, while /conf remained intact because /var/flasher.initcomplete was absent. Running the script separately with that guard satisfied reduced /conf from 102 entries to the 72-entry factory skeleton.

This proves the script is destructive and the command invokes an asynchronous path. It does not prove end-to-end command-to-wipe execution on the vBMC or production hardware, and it does not support the former authentication-bypass claim.

Evidence boundary

  • Dispatch identity, privilege, request-length constraint, and interface field: high confidence from the ASMB-787 registration entry.
  • Asynchronous task invocation: static analysis plus vBMC acceptance and subsequent reprovision activity.
  • Script destructive behavior: independently executed with its guard satisfied.
  • Exact task-to-script edge and production-hardware completion: not proved.
