Safety definitions and counts

Safety describes the known effect, not whether zipmi permits execution. When one recovered firmware row combines behaviors, the displayed class is the highest known impact and the row says so.

Read-Only 4 operations

Reads state and has no known persistent or service effect.

Sensitive 0 operations

Reads or changes credentials, trust, sessions, raw memory, firmware-control state, or other security-sensitive material.

State-Changing 0 operations

Changes configuration or runtime state without a known service interruption or data deletion.

Disruptive 0 operations

Can interrupt a service, session, device, or management connection.

Destructive 0 operations

Can erase data, reset configuration, or replace firmware or persistent state.

Unknown 0 operations

Available evidence does not establish the external effect.

Inventory scope and known gaps

Only four read-only handlers have reviewed execution contracts. Registration metadata selector_prefix_raw is never treated as request data; only the separately reviewed 0x32/0x44 selector 0 is auto-prefixed. A registration proves dispatch, not handler safety, runtime feature state, or response schema.

Live evidence

Four no-mutation probes were captured on the disposable XD670 zBMC guest. 0x32/0xa6 and 0x32/0x44 succeeded; 0x30/0xe0 returned 0xc7 and 0x32/0x9d returned 0xff. Error completion codes are not reported as success.
